About these columns

Data quality

Rows the migration could not load (rejects) and rows that loaded but need a look (quality issues), from the latest ETL run of each phase. Record what the team decided right here.

How to read these numbers

All numbers use only the latest run of each ETL phase. Older reruns are ignored.

  • Unresolved rejects: rows in Access that did not load into the database and are not yet marked Accepted as is or Resolved.
  • Unresolved quality issues: rows that did load but were flagged for a look, and are not yet closed.
  • Not yet looked at: issues still at status Open. Nobody has touched them; this is the team's to-do count.
  • Closed: share of all issues marked Accepted as is or Resolved. It climbs as the team works.
  • Phases reconciled: how many ETL phases pass the check "source rows = loaded + rejected" (see Run reconciliation).

Why rows were rejected or flagged

One card per issue code, most unresolved first.

How to read these cards
  • One card per issue code, with the most unresolved first.
  • Reject (orange) = the row did not load. Quality (blue) = it loaded but needs a look.
  • What to check is the concrete step to investigate it, usually in the Access database.
  • The footer shows which source tables the issues come from and how many distinct sites they affect. If many issues share a few site codes, fixing those sites in Access clears a lot at once.
  • The big number is unresolved issues for that code, out of the total. The green bar is the share already closed.
  • Show issues ↓ filters the issue list below to that code.

How to read this
  • One bar per Access source table (top 10, largest first). Only unresolved issues are counted.
  • Orange = rejects (not loaded), blue = quality issues (loaded, flagged). The number is the total.
  • It shows where the cleanup work is. Mostly orange means rows need fixing in Access and a rerun. Mostly blue means loaded rows need a team decision.
  • Hover for the exact split. Click a bar to list that table's issues below.
  • Bars shrink as issues are marked Accepted as is or Resolved.

Run reconciliation

Latest run per phase: source rows = loaded + rejected.

How to read this
  • One row per ETL phase (its latest run). Source = rows read from Access, Loaded = rows put in the database, Rejected = rows that did not load.
  • ✔ Reconciled: Source = Loaded + Rejected and every rejected row is logged in the issue list. Nothing was silently lost.
  • ⚠ Check: the numbers don't add up. Investigate before trusting that phase's data.

How to use this list
  • Shows All unresolved by default. Change Status to see closed issues too.
  • Click a row to see the full message, what to check, the original Access record (rejects) and the history, and to record a decision.
  • Tick boxes (or Select all shown) to record one decision for many issues at once, e.g. all rejects for one site code.
  • Statuses: Open → In review → Needs source fix (fix in Access, then rerun) or Needs ETL rule change → Accepted as is or Resolved.
  • Decisions stay attached to the issue even after the ETL is rerun.
